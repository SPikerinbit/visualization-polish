\section{Conclusion}
\label{sec:conclusion}
A semantic sort must decide both what to rank in each call and how much of the order to produce. Our multi-way merge uses sliding windows or segmented loser trees to reuse the order in its input runs. Full drains these groups by pass; \LIMIT~$K$ pulls only as far as the root needs. The planner compares feasible groups and fan-ins by estimating both repeated prompt overhead and repeated row appearances for the requested output.
