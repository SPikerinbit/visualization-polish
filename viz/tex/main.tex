\section{Scope}
The five source files named in \texttt{evidence/manifest.json} match the
browser-download manifest in both byte length and SHA-256.
Their commit is \texttt{0d96d0bf116e52f1664ae2539446f05921f5e947}
on branch \texttt{OperatorSemanticOrderBy}.
An earlier 40-character string that differed in two hex digits was a
transcription error, not another push.
No trailing wrapper was present, so nothing was stripped and nothing
outside the files was executed.
The pseudocode follows those files.
\texttt{prepare\_merge\_plan}, \texttt{init\_plan}, and the producer
shutdown that follows an early stop are imported but not among the five
files; those steps are named and left unread.
Model names \texttt{Qwen3.5-9B} and \texttt{Qwen3.8-27B} are the
configuration labels in the 2026-11-16 decision text.
This supplement does not check them against a model card.

The rejected manuscript listed three merge families and a dynamic
window $h=\lfloor m/|A|\rfloor$.
The verified LT file has one generator, and a fixed SW quota is used
whenever $h$ is passed ($h$ times the fan-in must fit in $m$).
The dynamic quota remains only as the fallback when $h$ is omitted.
Old measured tables are not reprinted.
The call-count formulas in the rejected manuscript are symbolic
statements of that manuscript, not a derivation from this commit.

\section{Mechanisms}
Blue fill is an item yielded to $\Pi$.
Blue stroke is a transient winner.
Red dash plus a small index is one \textsc{ListwiseRank} of real items.
Gray fill is a stored loser or a row kept in the SW buffer.
Hollow items are unread.
The pointer is a thick arrow and a tree edge is a thin line.

\section{Pseudocode}
After every multi-row LT rank, run-order repair keeps each input run's
own order. The model only chooses among the current heads.
The rejected draft's separate binary tree, power-of-two null leaves,
and \texttt{FullSlidingWindowMerge} initialization are not this code.
